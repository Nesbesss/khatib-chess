An earlier version of this table used a 30-position suite, where the same comparison swung by two positions between runs. Fifty-five positions is still small, so treat the gap to Stockfish as approximate. Stockfish is a far more mature engine and this doesn't claim to match it — it searches to depth 47 where Khatib reaches 12.

Every version earns its place

A network ships only after beating the one before it over hundreds of games. v10 won by +56 ± 14 Elo across 800 games; v11 beat it by +15 ± 11 Elo across 560 games, and v12 beat v11 by +12 ± 10 Elo across 800.

Four attempts to beat v7 failed first, at −266 to −308 Elo each. They ruled out the architecture and uncovered two real bugs: half the training labels had inverted signs, and training silently pushed the weights somewhere 16-bit export could not represent. v10 fixed both and fine-tuned v7 rather than starting over.

Where it actually stands

On Lichess as @nesbes: 2286 blitz over 236 games, 2437 bullet (provisional). 325 games played, 240 won.

Against Weiawaga 6.0.0, a mature Rust engine, Khatib scored 0 wins, 36 losses, 4 draws over 40 games at 10+0.1 — roughly 500 Elo behind. No time losses, so that is a straight playing-strength gap, not a clock problem. Weiawaga has singular extensions and a fully tuned parameter set; Khatib has neither yet. Both are on the list.

Search speed on an M4 Mac mini, one thread: 1.63M nodes/second, depth 17 from the start position in 7.6 seconds.

Install

Needs Rust. Builds in about a minute.

git clone https://github.com/Nesbesss/khatib-chess
cd khatib-chess
cargo build --release

./target/release/chess          # UCI mode, for any chess GUI
./target/release/chess serve    # search visualizer

Play against it

Khatib speaks UCI, so any standard chess program can use it. Install a free GUI — Cute Chess, Arena, or BanksiaGUI — and point it at the binary.

On Lichess it can run as a real bot account anyone can challenge. Chess.com has no way to connect your own engine, and using one in their games is a permanent ban — so Lichess is the place for this.

Inside

EvaluationNNUE, 768×8 → 1536×2 → 8 buckets
ThreadingLazy SMP, depth 19 → 22 on 8 threads

Every change was accepted or rejected by playing hundreds of games, never by node counts — those misled repeatedly.
